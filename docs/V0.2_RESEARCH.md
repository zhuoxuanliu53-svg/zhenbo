# V0.2 调研：夜间配色与卸载后文件

调研日期：2026-09-20。本文是开发依据，不作为主界面的说明文案。

## 夜间界面

没有证据支持把某一种 RGB 颜色叫作“最护眼”或保证助眠。夜间光影响取决于到达眼睛的光强、光谱、接触时间和个体差异。健康成人光照共识建议睡前降低 melanopic EDI、睡眠环境尽量暗；这不是可以直接换算成手机亮度百分比的指标。[Brown 等，PLOS Biology，2022](https://journals.plos.org/plosbiology/article?id=10.1371/journal.pbio.3001571)

屏幕实验中，视觉亮度和颜色相同但 melanopsin 刺激不同，仍可改变部分睡眠和褪黑素指标；研究使用专门校准的显示器、72 名年轻健康男性，不能据此声称普通主题配色具有相同效果。[Schöllhorn 等，Communications Biology，2023](https://www.nature.com/articles/s42003-023-04598-4)

另一项 16 人实验在保持 melanopsin 刺激一致时，未发现蓝／黄色变化对其测量的昼夜节律和睡眠指标有确切差异。因此，“暖色看起来舒服”与“已证明改善睡眠”应区分。[Blume 等，Nature Human Behaviour，2024](https://www.nature.com/articles/s41562-023-01791-7)

V0.2 的工程选择是近黑暖灰底、柔和文字和少量低饱和琥珀强调，减少亮色面积，同时保持可读性。这是视觉设计取舍，不是医学效果承诺。

| 用途 | 建议颜色 |
|---|---|
| 页面背景 | `#100E0C` |
| 卡片／浮层 | `#1C1916` |
| 稍高层次 | `#26211D` |
| 正文 | `#D8D0C4` |
| 次要文字 | `#B6AEA2` |
| 强调 | `#C6A477` |
| 强调色上文字 | `#221A10` |

按 sRGB 相对亮度计算，正文／背景约 12.60:1、次要文字／卡片约 7.97:1、强调色／卡片约 7.48:1。保持文字可读，不能单纯把所有文字压暗。对比度计算依据 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，最终还需检查实际组件的透明度与背景叠加。

实施时避免纯白大卡片、鲜亮大背景和常亮屏幕；封面保留辨认价值，控制展示面积。尊重系统亮度设置，允许用户结合系统夜间模式／额外调暗。播放后可以直接锁屏，屏幕熄灭比持续看某种配色更直接地减少屏幕光。不同 OLED／LCD、亮度档位、自动亮度和频闪表现仍需目标手机体验；本次不测量光谱，也不宣称主题达到某个 melanopic EDI 阈值。

## 卸载、重装与重名

已成功导出的 `Music/静听/` 音频属于公共媒体，通常会在卸载后保留；原始媒体也不会被静听卸载删除。重装后，系统不会把旧导出自动当作本次安装所拥有的文件，需重新获得读取授权并扫描，或由用户通过文件选择器选入。[Android 共享媒体与归属规则](https://developer.android.com/training/data-storage/shared/media#app-attribution)

对本应用支持的系统，Android 10–12 使用媒体读取权限，Android 13+ 使用音频读取权限 `READ_MEDIA_AUDIO`。官方共享媒体文章的重装段落仍使用旧权限名称，实施时应结合 [Android 13 细分媒体权限](https://developer.android.com/about/versions/13/behavior-changes-13#granular-media-permissions)。没有授权时看不到旧文件，不代表文件消失。

检查当前 `AudioExportService.kt`：通过 MediaStore `insert` 创建新条目，仅写返回的新 URI，文件名带毫秒时间戳；不会根据旧文件路径覆盖写入。已有目录可以继续使用。AOSP MediaProvider 还会生成唯一文件名处理重名，但具体后缀属系统实现，不在 UI 中承诺格式。[AOSP 唯一文件名实现](https://android.googlesource.com/platform/packages/providers/MediaProvider/+/8e3c6bd122b2e42fd4a35659438060caa5448784/src/com/android/providers/media/util/FileUtils.java)

因此，目录留下来本身不会造成冲突；重复提取同一个视频会产生新的音频副本，也不会自动恢复以前的集合。应用私有数据库、集合、播放记录、定时和本地显示名称在正常卸载时会清除；本应用关闭备份。覆盖安装升级与卸载重装不同，使用相同签名和包名直接升级可保留应用数据。[Android 应用专属存储](https://developer.android.com/training/data-storage/app-specific)

建议将用户可见解释收在设置的“存储”详情中，主界面不常驻：**“导出音频保存在 Music/静听，卸载后保留。集合和定时保存在应用内，卸载会清空。”**

后续验证应分别检查：覆盖升级保留集合；卸载重装后授权扫描旧导出；再次导出不覆盖旧文件；未授权时给出可操作的授权入口。本文核查文档与代码，不代替这些设备测试。
