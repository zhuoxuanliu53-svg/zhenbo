# V0.3 音频导出与原音质提速

V0.3 把“只换容器”与“重新编码”分开。视频、音频和两者混选都能直接作为拼接源，不需要先手动提取音频。输出仍经私有临时文件、MediaStore pending 发布；取消或失败会清理未完成文件。

每次导出完成只读取和登记新输出的 MediaStore URI，不再逐项扫描整个手机媒体库，避免批量提取重复进行全库扫描；用户主动刷新仍保留原来的扫描功能。

## 默认：保留原音质

| 音轨情况 | 实际处理 | 结果 |
| --- | --- | --- |
| 一个 AAC 音轨，或全部 AAC 且参数一致 | `MediaExtractor` 取原压缩包，`MediaMuxer` 写入单条音轨；不调用编码器 | M4A，音频压缩包内容不变 |
| 编码不同但采样率相同，单声道或双声道 | 解码到 PCM，直接保存 IEEE float WAV；原 PCM WAV 绕过系统降位深转换 | WAV，无二次有损编码；文件较大 |
| 不同采样率 | 导出对话框禁用“保留原音质”，提示选择兼容 AAC；不自动切换 | 用户明确选择后才转换 |
| 多声道、无法保留位深、WAV 预计超过 4 GB | 明确提示不支持该原音质合并方式 | 不静默降质、混声道或生成残缺文件 |

AAC 快路径逐一校验 MIME、采样率、声道数、AAC profile 与 `csd-0` / `csd-1` / `csd-2` 字节。缺少关键配置或配置不同不能视为相同音轨。码率不同本身不会改变解码配置，因此不要求码率一致。每个输入只选第一条音频轨，忽略视频和字幕。

每段以其第一个音频包为时间原点，按原间隔写入，后一段从上一段末尾继续。负的初始时间戳也被归一化。最后一个包通过 EOS 时间戳明确其持续时间。不删除 AAC 编码器原本的 priming / padding；原音质复制保留完整包，所以拼接点可能带有原压缩文件已有的短填充，不承诺采样级无缝。若源时间戳倒退、包加密或不完整则报错，不自行改变包内容。[MediaExtractor](https://developer.android.com/reference/android/media/MediaExtractor)、[MediaMuxer](https://developer.android.com/reference/android/media/MediaMuxer)

WAV 输出采用 32 位 IEEE float：16 位、24 位整数 PCM 都能精确表示；单声道合入双声道时左右复制同一数值，已有立体声不混为单声道。采样率不变，不做淡入淡出、归一化、重采样或抖动。32 位整数 PCM 无法被 float32 全部精确表示，因此暂不走该路径。FLAC / ALAC 等无损编码必须能确认位深，超过可精确表示范围则拒绝；解码器降低已知源位深则报错。有损 AAC / MP3 不存在可恢复的录音前 PCM，部分系统解码器原生只提供 16 位；WAV 精确保存设备实际解码的每个 PCM 值，不再量化或有损编码，不把它描述成恢复录音前原始信号。[MediaCodec 的原始音频缓冲区](https://developer.android.com/reference/android/media/MediaCodec#raw-audio-buffers)

Android 原生 WAV 提取器在普通应用进程中可能将 24 位 / float WAV 转成 16 位。V0.3 直接读取 RIFF `fmt` / `data`，支持 PCM 8 / 16 / 24 位与 float32，避免这一步降低精度；无法确认位深时拒绝“保留原音质”路径。参考 [AOSP WAVExtractor](https://android.googlesource.com/platform/frameworks/av/+/refs/heads/main/media/module/extractors/wav/WAVExtractor.cpp)。

## 可选：兼容 AAC

用户明确选择后，使用 Media3 Transformer 输出 48 kHz、双声道、AAC 256 kbps；可将不同编码、不同采样率的视频和音频直接拼成一个 M4A。它是有损重编码，不能称为无损；可能比原音轨复制慢。这是格式统一本身的成本，设备的硬件、编解码器和存储速度也影响耗时。[Media3 转换操作](https://developer.android.com/media/media3/transformer/transformations)

## 验证方法

`V03ExportTest` 包含七项独立设备测试：

- 单视频提取：输出只有 AAC 音轨，每个压缩包的 SHA-256 及包顺序与输入完全一致。
- 视频＋视频＋音频拼接：按给定顺序拼接，逐包核对三个源的哈希序列；检查总时长。
- 24 位立体声 WAV＋16 位单声道 WAV：逐个 float 样本零容差比对，检查左右声道及声道复制。
- 不同采样率：默认模式拒绝，预检给出原因；显式 AAC 模式成功输出。
- 同采样率不同编码：视频音轨＋WAV 直接输出音频 WAV，检查声道和时长。
- 原音轨复制运行中取消：不发布残缺输出，临时目录清理，源文件包序列保持不变。
- 120 秒 AAC 测试源：分别执行原音轨复制和原有 Transformer 编码路径，包含发布耗时；快路径再次逐包核对，写出 `files/v03-export-benchmark.json`。测试不靠把音质调低来获得速度，报告实际设备和实际耗时，不承诺任何固定倍数。

运行示例（项目构建并安装后）：

```powershell
python tools/generate_v03_export_fixtures.py
adb shell am instrument -w -e class app.jingting.localplayer.V03ExportTest app.jingting.localplayer.test/androidx.test.runner.AndroidJUnitRunner
adb exec-out run-as app.jingting.localplayer cat files/v03-export-benchmark.json
```

实际运行结果和设备范围以 V0.3 总测试报告为准。本文件描述机制与验证方法，不代替运行结果。
